# Loop Graph Interaction Features

## Problem Statement

The loop animation feature in duo-chrome uses a graph-based closed-walk algorithm to generate seamless image sequences. Currently, this graph exists only internally as a computational structure—users cannot visualize it, interact with it, or modify loop properties without full regeneration. This limits creative control and makes the algorithm's behavior opaque.

The graph structure itself is powerful but hidden:
- **Nodes**: All valid image pairs (a, b) where a ≠ b
- **Edges**: Adjacent states that share exactly one image
- **Cached**: Expensive to build ($O(S^2)$ neighbor checks), reused across generations
- **Stateless**: Contains pure transition rules, no rendering or color information

We need to expose this graph structure through visualization and interaction, enabling users to understand, manipulate, and creatively control loop generation without sacrificing performance.

## Requirements

### Functional Requirements

1. **Color Palette Changes Without Regeneration**
   - Users can switch color palettes while preserving the current walk sequence
   - "Randomize Colors" button shuffles color assignment without changing image pairs
   - Optional per-frame color picker for advanced customization
   - Changes apply instantly to playing or paused animations

2. **Graph Topology Visualization**
   - Interactive force-directed graph layout showing all valid state transitions
   - Visual representation of nodes (image pairs) and edges (valid transitions)
   - Current walk path highlighted within the full graph
   - Zoom, pan, and node inspection capabilities

3. **Manual Walk Construction**
   - Click-to-build interface for constructing custom paths through state space
   - Real-time validation showing which nodes are valid next steps
   - Visual feedback for adjacency constraints
   - Automatic loop closure detection when path returns to start

4. **Walk Constraints and Preferences**
   - Mark specific image pairs as "must include" or "forbidden"
   - Lock certain frames in the sequence while regenerating others
   - Prioritize certain transition types (e.g., A-swap vs B-swap)

### Non-Functional Requirements

1. **Performance**: Graph operations and visualization should not impact animation playback
2. **Responsiveness**: All interactions should feel immediate (<100ms feedback)
3. **Accessibility**: Visualization should work with keyboard navigation
4. **Memory Efficiency**: Large graphs (100+ nodes) should render smoothly
5. **Progressive Disclosure**: Basic features simple, advanced features available but not overwhelming

## Technical Approach

### 1. Decouple Color Assignment from Walk Generation

**Current Architecture:**
```javascript
// Walk generation triggers color assignment
generateWalk() → assignLoopFrameColors() → loopFrameColors[]
```

**Proposed Architecture:**
```javascript
// Independent color management
loopFrameColors = {
  frames: [...],          // Current walk sequence (immutable)
  colorAssignment: [...], // Separate color mapping (mutable)
  palette: colorIndex     // Active palette
}

// User actions
changePalette(newIndex) → reassignColors() → immediate visual update
shuffleColors() → randomizeColorMap() → immediate visual update
```

**Key Changes:**
- Move `loopFrameColors` to separate color management module
- Add `ColorAssignmentManager` class with palette-switching methods
- Expose palette controls in `LoopAnimationPanel`
- Update `onFrameChange` callback to use separated color source

### 2. Graph Visualization Component

**Technology Stack:**
- **D3.js** for force-directed layout and SVG rendering
- **Canvas fallback** for very large graphs (>200 nodes)
- **Separate panel/modal** to avoid cluttering main UI

**Data Structure:**
```javascript
GraphVisualization {
  nodes: [{ id, pair: {a, b}, x, y, selected, locked }],
  edges: [{ source, target, isInWalk }],
  walkPath: [nodeId1, nodeId2, ...],
  
  // Methods
  render(),
  highlightPath(walk),
  onNodeClick(nodeId),
  exportSVG()
}
```

**UI Integration:**
- New "Visualize Graph" button in LoopAnimationPanel
- Opens modal/overlay with interactive graph
- Current walk highlighted in graph
- Updates in real-time as walk changes

### 3. Manual Walk Construction Interface

**Interaction Model:**
```javascript
WalkBuilder {
  currentPath: [],
  validNextNodes: Set,
  canClose: boolean,
  
  // Methods
  addNode(nodeId) → validates adjacency
  removeLastNode() → backtrack
  autoComplete() → finds shortest path to closure
  reset()
}
```

**Visual Design:**
- Graph nodes colored by state:
  - Gray: Not yet visited
  - Blue: In current path
  - Green: Valid next step (adjacent to current)
  - Red: Invalid (not adjacent)
  - Gold: Can close the loop
- Click to add node, right-click to backtrack
- "Auto-complete" button finds shortest closure path

### 4. Constraint System

**Constraint Types:**
```javascript
WalkConstraints {
  mustInclude: Set<nodeId>,
  forbidden: Set<nodeId>,
  lockedFrames: Map<frameIndex, nodeId>,
  preferences: {
    preferASwaps: boolean,
    preferBSwaps: boolean,
    balanceSwapTypes: boolean
  }
}
```

**Integration with Generation:**
- Modify `selectNextState` in `closed-walk.js` to respect constraints
- Filter candidate nodes based on constraint rules
- Fallback gracefully if constraints make loop impossible

## Implementation Steps

### Phase 1: Color Palette Decoupling (Quick Win)

1. **Create ColorAssignmentManager Module**
   - Extract color logic from `generateLoopFrameColors()` in duo-chrome.js
   - Create `ColorAssignmentManager` class in `utils/loop-color-manager.js`
   - Methods: `assignFromPalette()`, `shuffle()`, `setFrameColor(index, color)`
   - Test suite for color assignment edge cases

2. **Add Palette Controls to UI**
   - Add palette dropdown to LoopAnimationPanel
   - Add "Randomize Colors" button
   - Wire up callbacks to ColorAssignmentManager
   - Update `onFrameChange` to use new color source

3. **Testing and Validation**
   - Test palette switching during play/pause
   - Test color randomization with different walk lengths
   - Verify no performance impact on animation playback

**Estimated Effort**: 4-6 hours
**Priority**: High (immediate value, low complexity)

### Phase 2: Graph Visualization (Educational)

4. **Graph Visualization Component**
   - Add D3.js dependency (or evaluate lightweight alternatives)
   - Create `GraphVisualization` component in `ui/GraphVisualization.js`
   - Implement force-directed layout with custom forces
   - Add zoom, pan, and node inspection

5. **Integration with Loop System**
   - Extract graph data from `ClosedWalkGenerator.graphCache`
   - Convert adjacency list to D3-compatible format
   - Highlight current walk path in visualization
   - Update visualization when walk regenerates

6. **UI Integration**
   - Add "Visualize Graph" button to LoopAnimationPanel
   - Create modal/overlay for graph view
   - Add export to SVG functionality
   - Keyboard shortcuts for visualization controls

**Estimated Effort**: 12-16 hours
**Priority**: Medium (educational value, moderate complexity)

### Phase 3: Manual Walk Construction (Advanced)

7. **WalkBuilder Module**
   - Create `WalkBuilder` class in `utils/walk-builder.js`
   - Implement adjacency validation for user-selected paths
   - Add auto-complete algorithm (shortest path to closure)
   - Test suite for path validation edge cases

8. **Interactive Graph Interface**
   - Extend GraphVisualization with click-to-build mode
   - Visual feedback for valid/invalid next steps
   - Display current path length and closure status
   - Undo/redo support for path construction

9. **Integration with Animation System**
   - Convert user-built path to standard walk format
   - Enable "Use Custom Walk" mode in LoopAnimationController
   - Persist custom walks across sessions (localStorage)
   - Allow switching between generated and custom walks

**Estimated Effort**: 16-20 hours
**Priority**: Low (power user feature, high complexity)

### Phase 4: Constraint System (Power Features)

10. **Constraint Definition UI**
    - Add constraint panel to LoopAnimationPanel
    - "Must Include" and "Forbidden" node selection
    - Visual representation of constrained nodes
    - Constraint validation feedback

11. **Constrained Walk Generation**
    - Modify `selectNextState` in closed-walk.js
    - Add constraint checking to neighbor selection
    - Implement graceful degradation if constraints conflict
    - Add constraint metadata to generated walks

12. **Testing and Edge Cases**
    - Test impossible constraint combinations
    - Verify performance with many constraints
    - Test constraint persistence across sessions

**Estimated Effort**: 10-14 hours
**Priority**: Low (advanced feature, medium complexity)

## Success Metrics

1. **Color Palette Feature**
   - Users can change palettes <100ms response time
   - No visual flicker or frame drops during transition
   - Color changes persist across page reloads (if desired)

2. **Graph Visualization**
   - Renders graphs up to 200 nodes at 60fps
   - Users can identify why loops fail/succeed at certain lengths
   - "Visualize Graph" feature used in >20% of loop mode sessions

3. **Manual Walk Construction**
   - Users can build valid walks without reading docs
   - <5% of manual walks end in unsolvable states
   - Custom walks shared/exported by advanced users

4. **Constraint System**
   - Constraints successfully applied >95% of the time
   - Graceful feedback when constraints conflict
   - Power users report increased creative control

## Risks and Mitigation

| Risk | Impact | Mitigation |
|------|--------|------------|
| D3.js adds significant bundle size | Medium | Evaluate lightweight alternatives (vis.js, sigma.js), lazy-load visualization |
| Graph visualization overwhelming for casual users | Medium | Progressive disclosure, hide behind "Advanced" toggle |
| Manual walk construction too complex | High | Extensive user testing, guided tutorial mode |
| Performance degradation with large graphs | High | Canvas fallback, virtualization, graph simplification options |
| Constraint conflicts confusing users | Medium | Clear validation feedback, constraint conflict resolution UI |
