# 02. Nx Testing Migration Strategy

## Problem Statement

The GenArt monorepo currently uses a hybrid testing approach that mixes proper Nx project-level test targets with legacy root-level package.json scripts. This creates inconsistency in how tests are configured and executed across applications, deviates from Nx best practices, and makes it difficult to scale testing as the monorepo grows.

### Current Issues
- **Inconsistent Test Configuration**: Only 2 out of 6 apps (duo-chrome, monochromifier) have proper `test` targets in their `project.json` files
- **Legacy Root Scripts**: App-specific test scripts like `test:crude-collage`, `test:computational-collage` exist in root `package.json` instead of proper Nx targets
- **Missing Nx Integration**: Apps without test targets cannot be tested using standard Nx commands (`nx test app-name`)
- **Scaling Challenges**: Adding new apps requires manual updates to root package.json rather than self-contained configuration

### Current State Analysis
**✅ Strengths (already implemented):**
- Comprehensive Playwright testing infrastructure (Task 17 completed)
- Excellent test utilities adapted from PolychromeText in `test/utils/p5-canvas-helpers.js`
- Thorough documentation in `docs/testing/`
- Working e2e tests for duo-chrome and monorepo integration
- Multi-app testing support via `TEST_APP` environment variable

**❌ Gaps requiring migration:**
- Missing test targets: crude-collage-painter, computational-collage, those-shape-things, dragline
- App-specific scripts in root package.json instead of project-level configuration
- No standardized test patterns across all apps

## Requirements

### R1: Nx-First Test Configuration
**Requirement**: All applications must have proper test targets in their `project.json` files that can be executed via `nx test app-name`

**Acceptance Criteria**:
- Each app has a `test` target using `@nx/playwright:playwright` executor
- All existing test functionality is preserved during migration
- Global test execution via `nx run-many --target=test --all` works correctly
- Individual app testing via `nx test app-name` works for all apps

### R2: Root Package.json Cleanup
**Requirement**: Remove app-specific test scripts from root package.json and retain only workspace-level commands

**Acceptance Criteria**:
- App-specific scripts (`test:crude-collage`, `test:computational-collage`) are removed
- Only workspace-level scripts remain: `test`, `test:e2e`, `test:e2e:ui`, etc.
- All existing test functionality remains accessible through Nx commands
- No breaking changes to CI/CD pipelines or developer workflows

### R3: Standardized Test Infrastructure
**Requirement**: Establish consistent test patterns and configuration across all applications

**Acceptance Criteria**:
- All apps use the same Playwright configuration patterns
- Shared test utilities work across all applications
- Each app has a basic smoke test to verify Playwright integration
- Documentation is updated to reflect the new Nx-first approach

### R4: Backward Compatibility
**Requirement**: Maintain all existing test functionality throughout the migration

**Acceptance Criteria**:
- No test capabilities are lost during migration
- All existing test files continue to work
- Performance characteristics are maintained or improved
- Existing CI/CD integration continues to function

## Technical Approach

### Architecture Overview
The migration follows Nx monorepo best practices by moving test configuration from the workspace root to individual project configurations. This approach provides:

- **Encapsulation**: Each app owns its test configuration
- **Scalability**: New apps are self-contained without requiring workspace updates
- **Consistency**: All apps follow the same configuration patterns
- **Maintainability**: Test configuration is co-located with app code

### Configuration Strategy
```javascript
// Target configuration for each app's project.json
{
  "test": {
    "executor": "@nx/playwright:playwright",
    "options": {
      "config": "apps/{app-name}/playwright.config.js"
    }
  }
}
```

### Shared Infrastructure Reuse
The migration leverages existing infrastructure:
- Playwright configuration base from root `playwright.config.js`
- Test utilities in `test/utils/p5-canvas-helpers.js`
- Documentation patterns from `docs/testing/`
- Multi-app support via `TEST_APP` environment variable

## Implementation Steps

### Phase 1: Project Configuration Migration (High Priority)
1. **Audit Current Test Targets**
   - Document which apps have test targets and which don't
   - Identify configuration patterns from existing targets (duo-chrome, monochromifier)
   - Map current root package.json scripts to target apps

   - Add test targets to crude-collage-painter project.json
   - Add test targets to computational-collage project.json
   - Add test targets to those-shape-things project.json
   - Add test targets to dragline project.json

3. **Create App-Specific Playwright Configs**
   - Create playwright.config.js for each app that needs one
   - Base configurations on existing root config with app-specific overrides
   - Ensure TEST_APP environment variable compatibility

4. **Validation Testing**
   - Test each app's test target individually (`nx test app-name`)
   - Verify all existing test functionality works
   - Test global command (`nx run-many --target=test --all`)

### Phase 2: Root Package.json Cleanup (High Priority)
5. **Remove Legacy Scripts**
   - Remove `test:crude-collage` and `test:computational-collage` scripts
   - Update any documentation referencing the removed scripts
   - Verify no CI/CD dependencies on removed scripts

6. **Standardize Workspace Scripts**
   - Keep `test`: `nx run-many --target=test --all`
   - Keep e2e scripts for global testing
   - Document the final script structure

### Phase 3: Standardization and Documentation (Medium Priority)
7. **Create Standard Test Templates**
   - Develop smoke test templates for apps without comprehensive tests
   - Ensure all apps have basic Playwright integration tests

   - Update docs/testing/ to reflect Nx-first approach
   - Update docs/guides/adding-projects.md with test target requirements
   - Create migration guide for existing developers

9. **Cross-App Validation**
   - Test the multi-app TEST_APP approach across all applications
   - Verify shared test utilities work with all p5.js instance mode implementations
   - Performance test the global test suite

### Phase 4: Advanced Features (Low Priority)

    - Implement parallel testing where beneficial

## Risks & Mitigation

### Risk 1: Test Configuration Conflicts
**Risk**: App-specific Playwright configs might conflict with shared utilities
**Probability**: Medium  
**Impact**: Medium  
**Mitigation**: 
- Use consistent base configuration across all apps
- Test configurations incrementally during Phase 1
- Maintain fallback to root configuration if needed

### Risk 2: CI/CD Pipeline Disruption
**Risk**: Changes to test scripts might break automated pipelines
**Probability**: Low  
**Impact**: High  
**Mitigation**:
- Audit CI/CD dependencies before making changes
- Implement migration during low-activity periods
- Maintain backward compatibility during transition

### Risk 3: Developer Workflow Disruption
**Risk**: Developers accustomed to legacy commands might be confused
**Probability**: Medium  
**Impact**: Low  
**Mitigation**:
- Create comprehensive migration documentation
- Provide command mapping (old → new)
- Implement gradual rollout with team communication

### Risk 4: Test Utility Compatibility
**Risk**: Shared test utilities might not work correctly across all app types
**Probability**: Low  
**Impact**: Medium  
**Mitigation**:
- Comprehensive cross-app testing in Phase 3
- Adapt utilities if needed for specific app requirements
- Maintain app-specific overrides where necessary
