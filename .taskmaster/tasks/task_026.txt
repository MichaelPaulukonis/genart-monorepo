# Task ID: 26
# Title: Configure Nx E2E Testing Targets for Improved Test Orchestration
# Status: deferred
# Dependencies: 18
# Priority: medium
# Description: Add proper Nx targets for E2E testing to leverage Nx caching, dependency graph, and parallel execution features across all applications in the monorepo.
# Details:
This task involves configuring Nx targets for E2E testing to take advantage of Nx's powerful features:

1. **Add E2E targets to each app's project.json**:
   - For each application, update the `project.json` file to include a `test:e2e` target:
   ```json
   {
     "targets": {
       "test:e2e": {
         "executor": "@nx/playwright:playwright",
         "options": {
           "testDir": "e2e",
           "config": "e2e/playwright.config.ts",
           "cacheDirectory": ".cache/playwright",
           "devServerTarget": "{app-name}:serve"
         },
         "configurations": {
           "production": {
             "devServerTarget": "{app-name}:serve:production"
           },
           "ci": {
             "workers": 4,
             "forbidOnly": true,
             "reporter": ["html", "json", "list"]
           }
         }
       }
     }
   }
   ```

2. **Create root-level E2E orchestration targets**:
   - Update the root `project.json` to include orchestration targets:
   ```json
   {
     "targets": {
       "test:e2e:all": {
         "executor": "nx:run-commands",
         "options": {
           "commands": [
             "nx run-many --target=test:e2e --all"
           ]
         }
       },
       "test:e2e:affected": {
         "executor": "nx:run-commands",
         "options": {
           "commands": [
             "nx affected --target=test:e2e"
           ]
         }
       },
       "test:e2e:verify": {
         "executor": "nx:run-commands",
         "options": {
           "commands": [
             "node tools/scripts/verify-e2e.js"
           ]
         }
       }
     }
   }
   ```

3. **Leverage Nx features**:
   - Configure caching by adding the following to `nx.json`:
   ```json
   {
     "tasksRunnerOptions": {
       "default": {
         "runner": "nx/tasks-runners/default",
         "options": {
           "cacheableOperations": [
             "build",
             "test",
             "test:e2e",
             "lint"
           ]
         }
       }
     }
   }
   ```
   - Set up dependency graph integration by updating each app's `project.json`:
   ```json
   {
     "implicitDependencies": ["shared-ui", "shared-utils"]
   }
   ```
   - Enable parallel execution by configuring the `--parallel` flag in the root commands

4. **Maintain custom verification script**:
   - Create a new script at `tools/scripts/verify-e2e.js` that wraps the Nx commands:
   ```javascript
   #!/usr/bin/env node
   const { execSync } = require('child_process');
   const chalk = require('chalk');
   
   console.log(chalk.blue('🧪 Running E2E verification suite...'));
   
   try {
     // Run the Nx command under the hood
     execSync('nx run-many --target=test:e2e --all --parallel=3', { stdio: 'inherit' });
     console.log(chalk.green('✅ All E2E tests passed!'));
   } catch (error) {
     console.error(chalk.red('❌ E2E verification failed!'));
     process.exit(1);
   }
   ```

5. **Update documentation**:
   - Create a new markdown file at `docs/testing/nx-e2e-testing.md`:
   ```markdown
   # Nx E2E Testing Guide
   
   This guide explains how to use Nx for E2E testing in our monorepo.
   
   ## Available Commands
   
   - `nx run {app-name}:test:e2e` - Run E2E tests for a specific app
   - `nx run test:e2e:all` - Run E2E tests for all apps
   - `nx run test:e2e:affected` - Run E2E tests only for affected apps
   - `nx run test:e2e:verify` - Run comprehensive verification suite
   
   ## Caching Benefits
   
   Nx caches test results to speed up subsequent runs. If no files affecting the tests have changed, Nx will use the cached results instead of re-running the tests.
   
   ## Dependency Graph
   
   To visualize the dependency graph including E2E tests:
   
   ```bash
   nx graph
   ```
   
   ## CI Optimization
   
   In CI environments, use the affected command to only test what's changed:
   
   ```bash
   nx affected --target=test:e2e
   ```
   ```

# Test Strategy:
1. **Verify E2E targets in project.json files**:
   - Check each app's `project.json` file to confirm the `test:e2e` target is properly configured
   - Validate that the executor is set to `@nx/playwright:playwright`
   - Ensure the configuration options are correctly specified for each app

2. **Test individual app E2E execution**:
   - Run `nx run duo-chrome:test:e2e` and verify tests execute correctly
   - Check that test results are displayed in the console
   - Confirm that the Playwright HTML report is generated in the expected location

3. **Test root-level orchestration commands**:
   - Run `nx run test:e2e:all` and verify it executes E2E tests for all apps
   - Run `nx run test:e2e:affected` with some changes and verify it only runs tests for affected apps
   - Execute `nx run test:e2e:verify` and confirm the custom verification script runs with colored output

4. **Verify caching functionality**:
   - Run E2E tests for an app twice without changes and check the second run uses cached results
   - Make a small change to the app and verify the cache is invalidated
   - Check the `.nx/cache` directory to confirm test results are being cached

5. **Test dependency graph integration**:
   - Run `nx graph` and verify E2E tests appear in the dependency graph
   - Confirm that the graph shows the correct dependencies between apps and their E2E tests
   - Make changes to a dependency and verify that affected apps' E2E tests are triggered

6. **Validate parallel execution**:
   - Run `nx run test:e2e:all --parallel=3` and monitor system resources to confirm tests run in parallel
   - Check the execution time compared to sequential runs to verify performance improvement

7. **Test CI integration**:
   - Set up a test CI environment or use a local simulation
   - Run the affected command with a base branch comparison
   - Verify only the E2E tests for affected apps are executed

8. **Documentation verification**:
   - Review the documentation to ensure all commands are correctly documented
   - Verify the documentation includes information about caching, dependency graph, and CI optimization
   - Test a few commands from the documentation to confirm they work as described
